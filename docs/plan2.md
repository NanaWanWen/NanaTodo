# YonErp Phase 2 完整实施计划

## 1. 目标

把当前采购订单系统升级为更适合面试展示的版本：

- 数据层：内置近半年约 300 条采购订单、明细、审批任务，保证报表、预警、AI 问答都有真实可查数据。
- 功能层：新增“工作台”首页，集中展示采购管理指标、趋势、排行、待办与 AI 提醒。
- 体验层：前端参考用友 BIP 与示例图风格，采用卡片式工作台、顶部导航/标签页、左侧功能入口、右下角智能问答悬浮入口。
- AI 层：智能问答基于当前用户数据回答“哪些订单逾期”“供应商排行”“库存预警”等问题；预警中心展示原因、风险、处理建议，并能跳转到业务单据。
- 权限层：修复 AI 对话记录跨用户共享问题，改为按登录用户隔离。

## 2. 数据流程

1. 启动后端时执行 `schema.sql` 建表。
2. 执行 `data.sql` 初始化基础数据。
3. 新增/更新近半年演示数据：
   - `po_order`：约 300 条，日期覆盖 2026-04-14 至 2026-10-14。
   - `po_order_item`：每单至少一条明细，金额按物料参考价和税率生成。
   - `po_approval_task`：为审批中订单生成有效审批任务，便于预警跳转处理。
4. 工作台统计接口读取：
   - 近半年订单总数、总金额、审批中、已审批、驳回、取消。
   - 供应商金额排行。
   - 低库存数量。
   - 逾期订单数量。
   - 待处理预警数量。

## 3. 工作台页面

新增 `/workbench` 作为登录后默认页。

页面结构：

- 顶部业务卡片区：采购完成率、准时交付率、异常订单、建议补货。
- 中间趋势区：近半年月度采购金额曲线。
- 右侧排行区：供应商金额排行。
- 底部提醒区：AI 预警摘要和快捷处理入口。
- 右下角智能问答悬浮按钮：点击打开 AgentChat 抽屉，不影响主页面。

## 4. 前端设计

参考用友 BIP 风格：

- 主色：企业蓝/科技蓝渐变。
- 布局：顶部导航 + 标签页 + 左侧功能分组 + 内容区卡片。
- 卡片：圆角 16px、柔和阴影、轻渐变背景、图标+数字+辅助说明。
- 图表：面积图/曲线图表达趋势，排行榜展示供应商。
- 智能问答：固定右下角，机器人头像 + 最近一条提醒，点击展开全屏或抽屉对话。
- 适配：桌面优先，宽度不足时卡片折叠为两列/一列。

## 5. 修复项

1. AI 会话按用户隔离：
   - 前端 localStorage key 改为 `yonerp.agentchat.history.v1.{userId}`。
   - 切换用户时读取对应历史，不共享另一个用户的对话。
2. 预警可处理：
   - 预警增加 `actionPath`。
   - 逾期订单跳转到订单详情。
   - 库存预警跳转到库存页。
3. AI 问答不编造数据：
   - 后端先查询真实业务数据，注入 LLM 上下文。
   - LLM 没输出结构化 JSON 时，后端自动补充可解析数据。

## 6. 验证流程

1. 启动 MySQL/Redis。
2. 启动后端，确认 `data.sql` 成功执行。
3. 调用工作台统计接口，确认返回近半年数据。
4. 以“张采购”和“李采购”登录，确认 AI 会话不互相显示。
5. 触发预警扫描，确认能生成逾期订单和库存预警。
6. 前端访问工作台，确认卡片、排行、趋势、智能问答入口可用。
7. 前端执行 typecheck，后端执行 compile/package。
